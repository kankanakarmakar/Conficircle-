# ConfCircle — Assumptions & Decisions

> Every design decision made where the spec was silent is documented here.

## Architecture Decisions

### AD-001: Monolith-first NestJS (not microservices)
**Decision:** Build a single NestJS app with feature modules instead of the microservice gateway+services structure already scaffolded in `backend/apps/`.  
**Reason:** The existing code is a stub scaffold without real business logic. A monolith is simpler to build, test, and run locally while satisfying all 10 flows. The OpenAPI contract and module boundaries mean migration to microservices is a later infrastructure decision.  
**Impact:** Single `api` app, single `worker` entrypoint, single Prisma schema.

### AD-002: Single Prisma schema
**Decision:** One `prisma/schema.prisma` at repo root covering all models from spec §4.  
**Reason:** Monolith approach. The existing per-service schemas are drafts and are archived.

### AD-003: BullMQ over RabbitMQ for jobs
**Decision:** Use BullMQ (Redis-backed) for background jobs instead of RabbitMQ.  
**Reason:** Spec says "BullMQ workers on Redis". RabbitMQ in existing docker-compose is kept for future use but workers use BullMQ.

### AD-004: JWT stored in Flutter Secure Storage only
**Decision:** Access token in memory + Flutter Secure Storage; refresh token in Secure Storage only.  
**Reason:** Spec §8 security rules; never expose via cookies or URL.

### AD-005: Signed playback URLs via local signing
**Decision:** Short-lived signed URLs for video playback use HMAC-SHA256 (symmetric signing) with 5-minute expiry, bound to userId.  
**Reason:** No S3/CDN configured; stub-compatible approach. Real implementations swap the signer.

### AD-006: Email/WhatsApp providers are stub adapters
**Decision:** Notification providers implement an `INotificationProvider` adapter interface. Default implementations log to console.  
**Reason:** No real provider credentials in spec; adapter pattern allows swap.

### AD-007: Guest TTL default = 3600s (1 hour)
**Decision:** `GUEST_TTL_SECONDS` env var defaults to `3600`, max `7200`.  
**Reason:** Spec §6 rule 6.

### AD-008: Quick Tip quota default = 3 per guest session
**Decision:** `GUEST_QUICKTIP_QUOTA` defaults to `3`.  
**Reason:** Spec says "within configured quota" without a number; 3 is reasonable and testable.

### AD-009: Video completion threshold = 90%
**Decision:** `VIDEO_COMPLETION_THRESHOLD` defaults to `0.9` (90%).  
**Reason:** Spec §8 "e.g. 90%".

### AD-010: Argon2 for password hashing
**Decision:** Use `argon2` npm package (argon2id variant).  
**Reason:** Spec §8 says "argon2/bcrypt"; argon2id is the stronger choice.

### AD-011: Flutter app structure — feature-first + clean architecture
**Decision:** Follow spec §3 exactly. Each feature has `presentation/`, `domain/`, `data/` layers.  
**Reason:** Spec is explicit.

### AD-012: OpenAPI spec location
**Decision:** OpenAPI YAML auto-generated by NestJS Swagger at `/docs` route; also exported to `/packages/api-contract/openapi.yaml`.  
**Reason:** Contract tests use the exported file.

### AD-013: `cupertino_icons` missing font
**Decision:** Add `cupertino_icons` package to `pubspec.yaml` dependencies.  
**Reason:** `flutter build web` warned about missing CupertinoIcons font.
